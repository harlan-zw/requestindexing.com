# Design — Request Indexing (Verdant Console)

> Generated by `nuxt-frontend-design`. This file is the source of truth for visual decisions across pages, components, and contributors. Compatible with the `@google/design.md` linter.
>
> Front matter holds machine-readable tokens. Prose below holds rationale, behavioural rules, and judgment.

## Aesthetic Direction

- **Theme**: Verdant Console — custom theme built on Nuxt UI's `emerald` + `olive` palettes. Not a stock theme; derives its voice from the product (indexing = pages going live = growth) rather than borrowed visual language.
- **Mode**: Both. Light is primary (marketing), dark is fully supported (dashboard).
- **Vibe**: Warm developer console — organic, technical, calm.
- **Influences**: Vercel (data clarity, monospaced rhythm in product surfaces), Linear (information density without coldness), Stripe Docs (typographic warmth in technical content). The product borrows their structure but trades cold gray for olive-tinted surfaces.
- **Design principle**: *We prioritise warmth over rigid austerity.* When two valid options exist, choose the one that feels more inhabited and less surveillance-grade. Emerald is the colour of growth, olive is the colour of soil — the tool nurtures, it does not police.
- **Personality of motion**: Quiet and utilitarian. 150–250ms `ease-out` for hovers and toggles. 300–500ms for entrance fades. Avoid bounce, elastic, or anything that draws attention to the animation itself. The tool should feel responsive, not performative.

## Color Decisions

| Role | Value | Why |
|------|-------|-----|
| Primary | `emerald` ({colors.primary}) | Growth, indexed pages going live, the moment Search Console flips a URL to "Indexed". Saturated enough to anchor CTAs against warm cream. |
| Neutral | `olive` ({colors.neutral}) | Warm yellow-green tinted neutrals. Avoids the corporate-gray default; reinforces the organic identity without competing with the emerald primary. |
| Success | emerald (matches primary) | Indexed status, positive deltas. Same hue as primary so the "winning" colour is unambiguous. |
| Warning | amber-500 | Pending indexing, quota approaching limit. Distinct enough from emerald to read as a different state. |
| Error | red-600 | Failed submissions, API errors. Used sparingly and only on real failures. |
| Info accent | blue-500 | Reserved for external Google links and informational callouts (the existing "Web Search Indexing API" pill). The only non-brand hue allowed in copy. |

- **Neutral tinting**: olive provides built-in warm tinting via Nuxt UI — no manual chroma adjustment needed. Light surfaces sit around `oklch(97% 0.01 90)`, dark surfaces around `oklch(18% 0.01 90)`. Never use `slate`, `gray`, `zinc`, or `stone` utilities — they break the tint.
- **60-30-10 split**: 60% olive-tinted surfaces (`bg-default`, `bg-muted`), 30% text + borders, 10% emerald accent on CTAs, status pips, and the verdant wash.

### Contrast & Accessibility

- **Body text contrast**: `text-default` on `bg-default` ≥ 12:1 in light mode (olive-900 on olive-50), ≥ 13:1 in dark mode (olive-50 on olive-950). Both well above AA.
- **Dark mode adjustments**: emerald primary stays at default saturation (it sits well against olive-950 without desaturation). Body text uses `--ui-text` directly — no manual weight reduction needed because DM Sans 400 reads cleanly at 16px on dark.
- **Known risks**: emerald-500 on white fails AA for normal-size text (≈3.4:1). Buttons are fine because text is white-on-emerald. *Never* set `text-primary` on `bg-default` for body copy — only for icons, badges, and links ≥ 14px semibold.

## Typography

| Role | Font | Why |
|------|------|-----|
| Body (`--font-sans`) | DM Sans | Clean grotesque, modern, distinct from Inter/Roboto. Reads well at 14–18px and pairs cleanly with Poppins headings. |
| Display (`--font-title`) | Poppins | Geometric rounded sans. Used on hero and section titles via the `font-title` utility. The roundness reinforces "warmth over austerity" — Plus Jakarta or Outfit would feel sharper and colder. |
| Mono | system monospace | No custom mono font registered. Used only for URL paths in dashboard cards (the existing hero mock URLs). Default `ui-monospace` keeps install cost down. |

- **Type system**: Fixed `rem` scale. The product is half marketing, half dashboard — fluid type would over-amplify hero text on mobile and under-scale dashboard data. Use Tailwind's `text-sm`/`text-base`/`text-xl`/etc.
- **OpenType features**: `font-feature-settings: "tnum"` on data tables and dashboard numerics for column alignment. Not enabled globally because tabular nums look stiff in body copy.
- **Heading conventions**: hero display is `text-5xl sm:text-6xl lg:text-7xl font-title font-bold tracking-[-0.03em]`. Section titles are `text-3xl md:text-4xl font-title font-semibold`. Body copy never uses `font-title`.

## Icons

- **Collection**: one active set, chosen in `shared/icons/index.ts`. Today that is `hugeicons`, with lucide, carbon and solar as per-role fallbacks. The registry below replaced the earlier mixed convention.
  - **Navigation & menus**: `i-ph-*-duotone` (Phosphor duotone). Warm, two-tone, friendly enough for a sidebar.
  - **Actions & controls**: `i-heroicons-*` (Heroicons outline by default, solid when active or selected).
  - **Brand marks**: `i-simple-icons-*` (only for third-party logos: GitHub, Google, Node.js, etc.).
- **Why mixed**: each collection earns its slot — duotone gives nav personality, heroicons keep buttons neutral, simple-icons stay accurate to brand identities. A single collection would force compromises on at least one of these.
- **Color rule**: monochrome inheriting from parent (`text-current`). Colour only for semantic meaning: `text-primary` on success states, `text-amber-400` on pending, `text-red-500` on errors, `text-blue-500` on Google links.

## Component Rules

> Behavioural constraints. Surface tokens (bg, text, radius, padding) live in the front matter under `components:`.

- **Buttons**: always specify `color` explicitly (`primary` for CTAs, `neutral` for secondary, never default). `variant="solid"` on primary CTAs, `variant="ghost"` on secondary actions, `variant="outline"` only when an outlined button needs to read as a peer of a solid one (rare).
- **Page cards (`UPageCard`)**: prefer `variant="outline"` with `spotlight spotlight-color="primary"` for marketing feature grids. Use `variant="subtle"` for trust/credential rows where outline would over-compete. Never wrap a `UPageCard` in another card.
- **Surfaces**: use Nuxt UI semantic classes — `bg-default`, `bg-muted`, `bg-elevated`, `text-default`, `text-muted`, `text-toned`, `border-default`. Do not write `bg-white dark:bg-neutral-900` — that hardcodes the dark mode and bypasses olive tinting.
- **Radius**: `rounded-xl` (20px) for primary surfaces (cards, hero panels). `rounded-lg` (14px) for inputs and small panels. `rounded-md` (10px, the global `--ui-radius`) for buttons and badges. `rounded-full` for avatars and pips only.
- **Focus rings**: rely on Nuxt UI defaults (2px primary with offset). Do not override per-component.
- **Status indicators**: `UBadge` with `color` + `variant="subtle"` for inline status. Do not invent custom pill components.
- **Hero card "preview"**: the dashboard mock card on the landing hero uses `shadow-2xl shadow-primary-500/10` (emerald-tinted shadow). Keep this pattern when showing product previews — primary-tinted shadows are a signature.

## Spatial & Motion

- **Spacing system**: 4pt base grid. Tailwind's `gap-1` through `gap-12` cover all rhythm.
- **Spacing philosophy**: generous on marketing (`py-16 md:py-20 lg:py-24` for sections), compact on dashboard (`py-4` per row, `gap-3` per metric). Marketing breathes; dashboard packs.
- **Section rhythm on landing**: hero → features → learn → data-retention horizontal → trust → FAQ → CTA. Alternate `bg-default` and `bg-muted` between sections only when the next block needs visual separation; flat consecutive sections are fine when content carries the rhythm.
- **Transition speed**: 150ms for hovers (`transition-colors`, `transition-transform`), 200ms for shadow lifts, 400ms for fade-in entrances.
- **Animation style**: subtle. The existing `.animate-fade-in` pattern (`opacity 0→1, translateY 4px→0, 0.4s ease-out`) with a 100ms stagger across siblings is the house style. Cap stagger total at 600ms — past that the user notices the wait.
- **Reduced motion**: respect `prefers-reduced-motion` for any entrance animation. Functional transitions (focus, hover) stay because they convey state.

## Responsive Strategy

- **Approach**: mobile-first. Three breakpoints in active use: `sm` (640px), `lg` (1024px), `xl` (1280px). Marketing pages also use `2xl` (1536px) for max-width caps.
- **Touch targets**: ≥ 44×44px on mobile. Buttons in the header collapse to icon-only on `< lg` to keep targets large without crowding.
- **Navigation**: header is `lg:`-and-up horizontal. Below that, `UHeader` falls back to a `body` slide-out with `UContentNavigation`.
- **Hero layout**: stacked single column on `< xl`, 7-5 split grid on `xl+`. The product preview card sits on the right at `xl+` and disappears below — do not move it above the copy on mobile.

## Avoid

> Hard rejections. Review will flag any of these.

- **Multi-hue gradients** (pink/blue/teal mixes, "rainbow" hero washes). Use `.bg-verdant` for any large branded background.
- **Hardcoded `bg-white dark:bg-neutral-900`** patterns. Use `bg-default`, `bg-muted`, or `bg-elevated`.
- **Hardcoded `text-neutral-700 dark:text-neutral-300`** patterns. Use `text-default`, `text-toned`, or `text-muted`.
- **`slate-*`, `gray-*`, `zinc-*`, `stone-*`** utilities anywhere. The neutral is olive.
- **Pure black** (`#000`, `bg-black`). Use `bg-inverted` or olive-950 via semantic tokens.
- **Inter, Roboto, Open Sans, Lato, Montserrat** — DM Sans + Poppins is the system.
- **Filled icons by default**. Outline is default, fill only for active/selected nav and status badges.
- **`shadow-2xl`** without a primary tint on product preview cards (the emerald-tinted shadow is part of the signature).
- **Bouncy or elastic easing**. Use `ease-out` or `ease-in-out` only.
- **Cards inside cards**. Use spacing and dividers for inner hierarchy.
- **Decorative SVG illustrations drawn inline**. Use real product screenshots, named brand logos, or labelled placeholder blocks.

## Design Decisions

> Append-only log of intentional choices the team has confirmed. Updated through `/nuxt-frontend-design` polish runs.

- **Emerald + olive palette is locked.** Confirmed at Phase 1 setup (2026-04-23). Changing primary or neutral is a brand-level decision, not a polish call.
- **Superseded by the semantic icon registry** (2026-09-15). `layers/design-system/shared/icons/registry.ts` maps every role (`next`, `delete`, `search`) to a real icon in four candidate sets, and `ACTIVE_ICON_SET` picks the one that renders. Roles resolve to `@nuxt/icon` aliases at build time, so `<UButton icon="next">` follows the active set. Write a role name, not a raw `i-*` id; a raw id still passes through for a brand mark the registry has no role for. Changing the active set is a brand-level decision.
- **The hero mock product card is part of the marketing identity.** Do not replace with an illustration or remove on small screens — drop it instead via `xl:` visibility.
- **Light mode is primary.** Dark mode must work but the marketing hero is designed for the light wash; the dark fallback is a deliberate de-emphasis (no animated gradient).
- **Emerald-500 + white button text is a documented contrast exception.** Raw ratio is 2.54:1 (below WCAG AA 4.5:1). Accepted because buttons are large bold targets, the brand identity depends on the brighter emerald, and Nuxt UI's button focus ring + hover state push the perceived contrast higher. Do not propagate `text-white on bg-primary-500` to body copy or non-button surfaces — that combination is forbidden.
- **Semantic colour aliases (`successAccent`, `warningAccent`, `errorAccent`, `neutralBg*`, `neutralBorder`) are documented in the front matter for reference but consumed via Nuxt UI components**, not via direct token refs in the YAML. Linter warnings about unreferenced tokens are expected and acceptable — removing them would lose machine-readable documentation of the palette.
- **Hero quick-feature grid trimmed to 3 items** (Request Indexing, Unified Dashboard, Data Retention). Open Source already appears in the trust section further down — keeping it in the hero double-stated value and competed with the product preview card.
- **`/request-indexing` route deleted.** Legacy v3-era landing page with deprecated `ULandingSection`/`ULandingCTA`/`ULandingCard` components, old colour names, and emoji copy. Not worth refactoring — `index.vue` covers the same ground better.
- **Pricing content is product, not design.** `pricing.vue` currently renders privacy-policy copy under a "Pricing" heading. Out of scope for the design refresh; flag separately for a content/product fix.
- **`.divider-tilt` is the canonical hero-to-next-section transition.** Defined once in `main.css`, applied via class — never re-hand-coded inline.
