# AI surface parity

Decision source: Harlan's 10 November 2026 parity sweep and rollout approval.

Done means: focused setup, Watched URLs, attributed activity, feedback correlation, and release checks work across the product boundary.
Production checks must use the deployment workflow's release.

## Ownership

- gscdump owns the evidence, watches, scheduled inspection, feedback intake, attribution, and partner activity contract.
- Request Indexing owns setup, consent, source labels, recovery, and the admin presentation of its activity.
- NuxtSEO supplies shared feedback closure and terminal outcome patterns.
- Each consumer uses published protocol packages. Never copy engine internals.

## Delivery slices

1. Connect Watched URLs through the registry, SDK, and browser allowlist.
   Keep recurring inspection spend consent beside the action.
   Confirm removal before deleting Checkpoints.
   Keep saved evidence visible after a failed refresh.
2. Make setup answer the indexing question.
   Link Developers from the public footer.
   Read retained indexing evidence in the API example.
   Keep Request Indexing's own recovery path in the copied prompt.
   MCP fallback must name saved reads and refuse missing capabilities without spending inspection quota.
3. Request sanitized paper-cut reports from the public skill and setup prompt.
   Use the existing `gscdump papercut` command.
   Join origin, operation, request, workflow, and skill identity when the released CLI supports those fields.
   Report intake failure once without retrying the report.
4. Adopt `partner.users.integration_activity.get` through its published SDK method.
   Let the engine enforce partner ownership and credential origin.
   Keep unavailable counts null. Do not infer MCP or CLI success from UI visits.
5. Complete feedback quality and closure through the engine's shared contract.
   Keep reported usefulness distinct from transport success.
   Preserve feedback ID, request correlation, triage state, fix reference, and release verification.
   Do not create a competing Request Indexing data API.
6. Gate skill publication on discovery digest and served content checks.
   Verify API examples against the published route registry.
   Exercise watched URL authorization, spend consent, partial refusals, and Site changes.
